## P1 — до запуску на prod-сервері

1. **PixiJS не стартує під CSP із `docs/deployment.md`.** Розділ «Content Security Policy» радить `script-src 'self'`
   (без `'unsafe-eval'`). Вбудований `vendor/pixi/8.22.0/pixi-scene.js` генерує функції синхронізації uniform і
   буферів через `new Function` і в `_systemCheck` кидає «Current environment does not allow unsafe-eval, please use
   pixi.js/unsafe-eval module». `utils/vendor-libraries.js` (`SCENE_SIDE_EFFECTS`) імпортує лише `pixi.js/filters`,
   модуля `pixi.js/unsafe-eval` у бандлі немає. Наслідок на сервері з такою CSP: WebGL-сцена падає на ініціалізації,
   гра непомітно йде запасним 2D-шляхом (Canvas 2D + `spine-webgl` з копіюванням GL → 2D), від якого spec 103 і
   переносила світ на WebGL. GitHub Pages CSP не ставить, тому зараз цього не видно.
   Рішення (технічне, без питань): додати `pixi.js/unsafe-eval` до `SCENE_SIDE_EFFECTS`, перезібрати vendor (хеш у
   маніфесті), перевірка `scene-layer` стверджує, що бандл реєструє ці системи, а тест під CSP-заголовком у
   `measure:startup --prefix root` показує сцену `webgl`. `'unsafe-eval'` у CSP не додаємо.
2. **Світ залежить від розміру вікна (G-126, [spec 153](../../specs/153-viewport-independent-world/spec.md)).**
   Рішення прийняті 2026-10-30, реалізації немає: межі фізики поплавка/риби/кораблика беруться з видимого екрана
   (`lockZoneXToScreen`), бокова частка бою — з ширини canvas. Звуження вікна — чит. Для публічного prod це
   виправлення гри, а не оптимізація; окремий ігровий коміт із перебазуванням game-cycle за правилами «Gameplay changes».
3. **Діагностика бою в production-консолі (G-001, відкритий з 2026-10-10).** Production-композиція
   (`game_composition_root.js:1477–1478`) дає `catchResolutionLogger` і `fightLogger` = `ConsoleLogger`. Тому кожна
   перемога автопідсікання друкує `groupCollapsed` + `table` ~40 полів (`catch_resolution_service.js:233–235`; поля з
   DEV-знімка бою в production — нулі), а `Fish` — `[DEBUFF]`/`[MASTERY]` (`fish.js:103, 188, 234`). Правило spec 020:
   production-консоль під час бою порожня.
   Рішення: діагностичний логер бою — порт; production компонує неактивну реалізацію (як 034–036),
   DEV — `ConsoleLogger`. Перевірка: production-композиція бою в game-cycle не викликає `log/table/groupCollapsed`.
   Game-cycle не змінюється.
4. **`npm run git:add` і `git:version-copy` роблять `git add .`** (`package.json`, `utils/git-version-copy.js:93`).
   Це суперечить правилу комітів (лише явні шляхи) і може закомітити невідстежувані файли власника (`zones-*.json`,
   `.agents/`, `.specify/`, `utils/local-bridge.js`). Інструмент власника (spec 039) → рішення власника (Q3).

## P2 — рішення для prod і відкриті кроки оптимізації

5. **Що містить prod-реліз.** Реліз однаковий для Pages і сервера (spec 157 R13) і несе `dev.html` з DevTools і
   cheat-командами, `src/dev/` (906 модулів графа проти 683 production), `src/` для `?esm=1` і source maps. Для
   тестового Pages це правильно; для публічного сервера — рішення власника (Q1).
6. **Spec 103 формально не закрита.** Етапи 3–4 (вода, сутності, Spine-вудка) реалізовано 2026-10-18, рядок статусу
   досі каже «phone check pending», етап 5 (прибрати 2D-рендерери сцени і `spine-webgl`, D5) не зроблено. 2D-шлях
   зараз — справжній запасний (немає WebGL, втрата контексту, P1-1), тож прибирати його лише після P1-1 і рішення Q2.
7. **Наступні кроки spec 102 не зроблені.**
   - Фон тестової локації 2560×1440; портрет при pixel ratio 2 потребує ≥ 1 632 px висоти (правило 7). Вартість
     прибрано spec 105 D4 (збільшене малюється 1:1, масштабує композитор), лишилась м'якість у портреті.
   - Адаптивний pixel ratio за часом кадру (Auto/Low/High, [spec 047](../../specs/047-smart-asset-preloader/spec.md) —
     Draft) — немає. Для слабких телефонів у prod це головний важіль після бюджету GPU (правило 9).
8. **Мережеві кроки старту понад 3.** На Fast 4G із CPU ×4 — 4; spec 157 це прийняла (SVG-спрайти кнопок
   `inventory-sections.svg`, `status-icons.svg` браузер просить під час композиції; ціль міряють на Fast 4G без
   сповільнення CPU). Нове: на 3G **без** сповільнення CPU медіана 3,5 (2 прогони). Решта бюджетів із запасом ×3–7.
   Кандидат: `preload` цих двох спрайтів у сторінці релізу (маленька TK, вимір до/після; якщо не дає кроку — закрити
   як прийняте).
9. **Клієнт авторитетний** (сейв, улов, валюта): бекенд ([spec 029](../../specs/029-backend-foundation/plan.md)) — лише
   план, звіту про помилки з клієнтів немає. Відомо й відкладено власником; для prod без бекенду гра лишається
   одиночною, прогрес — у `localStorage`.

## Питання власнику

- **Q1. Prod-сервер без DEV?** Рекомендую: окремий режим релізу `--production` — без `dev.html`, `src/dev/`, із
  source maps поза публічною текою; Pages лишається повним тестовим релізом.
- **Q2. 2D-шлях сцени лишається запасним?** Рекомендую: лишити, доки не зібрано статистику пристроїв без WebGL;
  етап 5 spec 103 відкласти, а її рядок статусу оновити.
- **Q3. `git:version-copy`:** прибрати `git:add` і зробити інструмент лише копією версії (коміт — вручну явними
  шляхами), чи видалити інструмент повністю?
- **Q4. `vinyl-5.mp3`:** перекодувати `convert-audio.js` (як VOLIA, зразки 32/48/64k) чи лишити як є?
- **Q5. Порядок:** spec 153 до публічного запуску (рекомендую) чи після кроків 1–4?
