## Boundary-tool evaluation

The existing observer, unified graph and guards enforce qualified layer/role dependencies, cycles, explicit module conventions, browser capabilities, globals, DEV leakage, exact bridge identity and reviewed migration imports. Dependency-cruiser supports forbidden/allowed dependency rules, unresolved dependencies and cycles; its graph reports would be useful for interactive exploration. Its integration would add a dependency/lockfile change, configuration mirroring the current layer policy, another graph traversal and an ongoing equivalence review. Source: [official rules reference](https://github.com/sverweij/dependency-cruiser/blob/main/doc/rules-reference.md).

ESLint Boundaries supports element dependency and entry-point restrictions. It would require ESLint/plugin integration and a mapping from the current manifest roles and qualified edges into another configuration. Source: [official entry-point rule](https://www.jsboundaries.dev/docs/rules/entry-point/).

Decision: retain the existing guards and negative fixtures; install neither tool. Their documented static dependency rules overlap current coverage, while exact migration/history/transport contracts must remain. Optional graph visualization is a future tooling benefit, not an architecture enforcement gap. The cost is avoided dependencies and duplicated configuration; no guarantee, baseline or whitelist is removed.
