# Spec 161 — Вікно перемоги в DOM (TK-230)

Статус: у роботі (2026-11-06). Задача власника — TK-230 у `tasks.md`.

## Проблема

Панель VICTORY малюється на 2D-полотні HUD (`VictoryRenderer`, `VictoryLayoutResolver`, `StarRatingRenderer`,
`VictoryActionGestureResolver`), а розмиття тла — фільтр `blur()` полотна на весь екран у кожному кадрі. За ролями
рендерингу ([docs/rendering.md](../../docs/rendering.md), spec 103) вікна — це DOM. Власник хоче: прямокутне зображення
з закругленими кутами (як у садку), натискання на рибу — плашка зникає, риба на весь розмір на розмитому тлі, повторне
натискання повертає плашку; плашки «вага», «трофей», «аномалія» — SVG-іконки замість тексту (кубок, знак радіаційної
небезпеки, статус — галочка або хрестик); під зображенням — сіра векторна шкала-лінійка ваги з мін/макс, поточною вагою
й зеленим відрізком трофейної ваги з її числом.

## Рішення

- **D1 (технічне, агент; власник 2026-11-06: «зроби максимально оптимізовано»).** Перемога — DOM-вікно, не полотно.
  Вікно будується один раз (лінива можливість `victory`), показ/приховування міняє класи й текст; жодної роботи в
  кожному кадрі. Розмиття — CSS `backdrop-filter` на шарі вікна (композитор), замість фільтра полотна в кожному кадрі.
  Полотно для перемоги більше нічого не малює.
- **D2.** Кнопки — справжні `<button>`; `VictoryState` отримує дію від вікна (`claim`/`release`), а не через
  hit-test полотна. Жест, що почався до відкриття вікна, не натискає кнопку (як було: вікно приймає дію лише після
  `pointerdown` усередині нього).
- **D3.** Кнопку «На живця» з перемоги прибрано: риба, що підходить для живця, стає живцем сама (spec 162).
- **D4.** Шкала ваги: мін/макс виду з `levelWeightRanges` (перший `min`, останній `max`), інакше з `depthConfig`
  (`minWeightAtMinDepth`…`maxWeightAtMaxDepth`); трофей — `trophyWeightKg` виду (немає — немає зеленого відрізка).
  Поточна вага — позначка з числом. 10 поділок.
- **D5.** Тема (колір рамки за рівнем, анімована для унікальної риби) — `VictoryThemeResolver` один раз при показі →
  CSS-змінні; анімація унікальної — CSS (`@keyframes`, лише `opacity` світіння), без JS у кадрі; `prefers-reduced-motion`
  її вимикає.
- **D6.** Іконки: вага — `ui.inventory.weight`; нові символи `trophy`, `radiation`, `check`, `cross` у
  `assets/ui/status-icons.svg` (`currentColor`).

## Модель

- `VictoryViewModelBuilder` (presentation): з риби й виду — назва, рівень, вага, трофей, аномалія, рідкість (зірки),
  шлях зображення (`FishArtVariants.displayImagePath`), шкала `{ minKg, maxKg, weightKg, trophyKg }`, тема.
- `VictoryWindow` (presentation, DOM через `domFactory`): `show(view, { onAction })`, `hide()`, `dispose()`; режим
  «риба на весь екран» перемикається натисканням на зображення / будь-де в цьому режимі; Escape повертає плашку.
- `VictoryState`: `enter` показує вікно, `exit` ховає; дія вікна → `liveBait.resolveCatch` → `scouting`.
- Видалено: `VictoryRenderer`, `VictoryLayoutResolver`, `VictoryActionGestureResolver`, `StarRatingRenderer`,
  гілку перемоги в `OutcomeRenderFrameBuilder`/проході результату; `CONFIG.ui.victory` лишає `blurPx`.

## Перевірки

- `victory-input-check` переписано на вікно: дії кнопок, жест до відкриття, режим повного зображення, Escape,
  приховування й `dispose` без слухачів, що лишились.
- Перевірка моделі: шкала (з діапазонами рівнів і без), трофей/без трофею, аномалія, зірки.
- Game-cycle без змін (перемога там — лише перехід стану).

зірок, кнопок; ПК.
