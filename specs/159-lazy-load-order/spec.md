# Spec 159. Порядок лінивого завантаження третього шару (TK-199, TK-200)

Статус: реалізовано, прийнято власником 2026-11-05 у проході spec 157.

## Проблема

Власник (2026-11-04): після старту завантажитись мають усі ресурси гри, крім закритих прогресом. Раніше група `on-demand`
(72 файли, 27.44 МБ) після старту не вантажилась зовсім, а `LazyImageWarmUp` тягнув low-копії з DOM поза чергою.

## Рішення власника

1. **Шари один і два:** оригінал вантажиться одразу після low-копії.
2. **Шар три — лінивий.** Порядок: low-копії фонів → low-копії предметів інвентаря → Spine → low-копії кімнати рибалки →
   решта low-копій. Потім оригінали в тій самій послідовності.
3. **Закрите прогресом** у ліниву чергу не входить: окрема черга `locked` у системі завантаження на вимогу.
4. Зрештою завантажуються всі ресурси гри, крім закритих і аудіо.
5. **Кімната рибалки (TK-216, замість TK-203):** вантажиться лише відкритий рівень, акваріум і ремонт; арт вищих рівнів у черзі `locked`, наступний рівень відкриває натиск «покращити». Пізніше список зображень віддаватиме сервер.
6. **Аудіо (TK-201):** поки що лише під час запуску радіо; у третьому шарі, група `audio` з `load: false`.

## Рішення за замовчуванням (питання власнику)

- **Що закрите сьогодні.** Нічого (TK-203). Новий закритий вміст додається в джерело `progress.locked`; коли прогрес його
  відкриває, композиція викликає `setProgress`.

## Модель

- План: шар `lazy: true` проходить двічі; група `locked: true` називає закрите через джерело й нічого не вантажить.
- `GameAssetPreloadFacade`: прохід low, потім прохід full за пріоритетами груп; закриті id відсіяні. `setProgress(state)`
  перераховує закрите, а відкрите одразу ставить у чергу (low, потім full).
- `isReady(id)` хибне, поки в сховищі лише копія: DOM показує копію й просить оригінал.
- Spine у фоні: `warmFile(path)` кладе файл у кеш браузера через ту саму чергу.
- `request()` гравця випереджає фон, у тому числі для закритого.
- `LazyImageWarmUp` прибрано: його роботу виконує третій шар через чергу.

## Перевірки

`asset-load-plan`: порядок проходів, виключення закритого, відкриття рівня, Spine, аудіо на вимогу, шар два (low, потім full),
`isReady`, виробничий план (нічого без місця, порядок груп). `measure:startup`, Full, game-cycle без змін.

## Приймання власником

Візуально агентом не перевірялося. Телефон, Pages `dev.html`, холодний старт, оверлей «ЗАВАНТАЖЕННЯ»:

1. Секція плану: група за групою стають «готово», `locked` показує «закрите».
2. Рюкзак відкритий одразу після старту: копії, за мить чіткі; після завершення шару три — одразу чіткі.
3. Поки радіо вимкнене, аудіофайли не вантажаться; увімкнути радіо — запис вантажиться й грає.
4. Група «Кімната рибалки» — усі 17 файлів, `locked` — 0 файлів.
5. «ПРОДУКТИВНІСТЬ» в обох орієнтаціях під час фонового завантаження й пам'ять після нього.
