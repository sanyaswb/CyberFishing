# Spec 186 — DEV overlay: огляд, надійність, продуктивність і зручність як у DevTools

Власник, 2026-11-23: «Тепер потрібно так само перевірити спочатку все що відноситься до overlay, твоя задача розробити
покращення для цього функціоналу, враховуючи як прокачався devtools, і перевірку вкінці зробити».

## Що є зараз (огляд коду, 2026-11-23)

- **Склад.** `src/dev/overlay` — ~6200 рядків, 25 модулів-вікон (`OverlayModule.render(data)` → рядок HTML), вікна
  «ACTIVE FISH / ROD» з повзунками (spec 168), композиція `debug_overlay_bootstrap.js`. Кожне вікно — `OverlayDomAdapter`
  (масштаб, перетягування, закриття), вміст оновлюється латкою DOM з нового HTML (`#patchChildren`, I-11).
- **Цикл.** `OverlayUpdateLoop` кожні `CONFIG.debug.overlayUpdateMs` (150 мс) викликає `OverlayController.update`: для
  кожного активного модуля будується весь HTML, порівнюється з попереднім, за зміни — розбір у тимчасовий елемент і латка.
- **Дані.** `DebugService.update` (`debug_service.js:13`) викликається **кожного кадру** з `GameApplication`
  (`game_application.js:805`), поки увімкнено overlay, модулі консолі або відкрито DevTools, і щоразу будує весь знімок:
  `getLiveChances` (`bite_system.js:540`) рахує шанс і розбивку з ~14 рядками `toFixed` для кожної риби бази, новий
  об'єкт `detail`, `baits.map`, `CustomEvent`. Усі споживачі (overlay, вікна балансу, DevTools, модулі консолі, пояснення
  метрик) лише запам'ятовують останній знімок і читають його у своєму ритмі (150 мс).
- **Пояснення метрик** (TK-217, TK-309): натиск на назву метрики пише формулу **в консоль** і відкриває параметр у
  DevTools. На телефоні консолі немає (I-29) — пояснення там недоступне.
- **Звіт завантаження** (spec 157): без буфера обміну — браузерний `prompt` (у DevTools заборонено, spec 174 C5).
- **Перемикачі модулів** (`OverlaySettingsStore`) живуть лише в пам'яті: після перезавантаження сторінки ввімкнені
  вікна повертаються до типових (у DevTools усе пам'ятається: сторінка, секції, налаштування панелі).
- **Вигляд:** заголовки з емодзі (34 місця в 16 файлах; у DevTools емодзі замінено іконками, spec 174 C1).

## Знахідки огляду

1. **Один модуль, що кидає помилку, зупиняє всі вікна після нього** (R29 для overlay не діє).
   `OverlayController.update` (`overlay_controller.js:85`) обходить модулі без ізоляції: виняток з `render` виходить із
   `update`, і кожні 150 мс той самий модуль обриває оновлення решти — вікна застигають без жодного знаку (на телефоні
   консолі немає). Той самий клас дефекту, що I-29 у DevTools.
2. **Знімок для overlay будується 60 разів на секунду, а читається ~7** (продуктивність DEV і точність заміру).
   Власник міряє телефон з увімкненим «ПРОДУКТИВНІСТЬ» — а саме увімкнений overlay додає щокадрову роботу й сміття
   (`getLiveChances` по всіх рибах, рядки, об'єкти), яких ПРОДУКТИВНІСТЬ не потребує. Замір перед зміною — в «Реалізації».
3. **Смуга кадрів «ПРОДУКТИВНІСТЬ» — 240 `<rect>` у HTML кожні 150 мс** (`performance_overlay_module.js:75`): рядок
   ~240 елементів, розбір браузером і латка атрибутів 240 вузлів ~7 разів на секунду в головному потоці телефона, який
   цей самий модуль і міряє.
4. **10 посилань метрик ведуть на групу, а не на параметр** (R20): наприклад «Active fish force» →
   `CONFIG.physics.fight.directionForce`; DevTools підсвічує заголовок закритої групи, сама група не розкривається.
   Перевірки, що шляхи каталогу метрик (`overlay_metric_descriptions.json`) існують у `CONFIG`, немає (зараз усі 32
   існують — перевіряв скриптом; майбутня помилка пройде непоміченою).
5. **Запасні варіанти й глобальні значення за замовчуванням** у ядрі (`documentTarget = document`, `timer = window`,
   `?.attach?.()`, `store.setEnabled ? … : modules[key] = …` в `OverlaySettingsModule`) — правило «без необов'язкових
   викликів для того, що є завжди».

## Рішення (агент)

- **D1 (знахідка 1, TK-391).** `OverlayController` оновлює кожен модуль окремо: помилка `render` показується у вікні
  цього модуля червоним блоком (назва, причина, «решта overlay працює»), у консоль — один раз на нову причину;
  наступні модулі оновлюються. Перевірка падає на старому коді.
- **D2 (знахідка 2, TK-392).** `DebugService` будує й надсилає знімок не частіше ніж раз на `CONFIG.debug.overlayUpdateMs`
  (ритм усіх споживачів), за ігровим годинником кадру; перший кадр після вмикання — одразу. Нічого, що споживачі
  показують, не губиться: вони й зараз читають лише останній знімок. Замір у Node до/після (час і алокації на секунду).
- **D3 (знахідка 3, TK-393).** Смуга кадрів — три `<path>` (зелений, помаранчевий, червоний) з одним атрибутом `d` кожен
  замість 240 `<rect>`; вигляд той самий.
- **D4 (знахідка 4, TK-394) — після перевірки не підтвердилась, змін немає.** Перевірка R20 для каталогу вже є:
  `config-schema-check` (TK-318) перевіряє, що кожен шлях `CONFIG.*` каталогу метрик існує. А посилання на групу
  розкриває групу: `DevToolsDependencyFeedback.showRevealed` для цілі-секції клацає її заголовок, якщо вміст закритий.
- **D5 (знахідка 5, TK-395).** Прибрати запасні варіанти й глобальні значення за замовчуванням у ядрі overlay та
  `OverlaySettingsModule` (колаборатори передає композиція).

## Питання власнику (зручність «як у DevTools») — відповіді 2026-11-23

- **Q1. Пам'ятати ввімкнені вікна overlay між перезавантаженнями?** Власник: **«Ні, лишити як є»** — після
  перезавантаження типовий набір вікон.
- **Q2 (TK-396). Пояснення метрики на екрані?** Власник: **підказка під рядком.** Натиск на назву метрики відкриває під
  рядком підказку як «i» у DevTools — що це, формула, параметри з поточними значеннями, кнопка «Відкрити в DevTools»
  для метрик із параметром; повторний натиск закриває; консоль лишається. Звіт завантаження без буфера обміну —
  діалог DevTools (`TextDialog`) замість `prompt`.
- **Q3 (TK-397). Іконки замість емодзі в заголовках вікон?** Власник: **так, іконки DevTools.** Ті самі SVG-іконки
  (`dev_icon.js`), однакові на всіх платформах; перевірка емодзі охоплює й `src/dev/overlay`.

## Перевірки

- `ui-surface` / нова частина `devtools-controls` або окрема перевірка overlay — модуль, що кидає, не зупиняє інші (D1).
- Сценарій `DebugService` з фіксованим годинником: 60 кадрів за секунду → ~7 знімків (D2), замір у «Реалізації».
- Смуга кадрів: кількість елементів не залежить від кількості кадрів (D3).
- Каталог метрик проти справжнього `CONFIG` (D4).
- У кінці — повний огляд коду всього, що змінено (за `docs/code_review.md`).

## Реалізація

- **TK-391 (v0.52.57, D1).** `OverlayController.#renderModule` обгортає `isActive` і `render` кожного модуля: помилка —
  `OverlayHtmlBuilder.errorBlock` у вікні цього модуля, у консоль одна причина один раз (`#errors`), наступні модулі
  оновлюються. Контролер отримує `htmlBuilder` з композиції. Перевірка `overlay-balance-windows` (модуль, що кидає, і
  модуль після нього: вікно з причиною, другий оновлюється двічі, одна помилка в консолі) падає на старому коді. R29.
- **TK-392 (v0.52.58, D2).** `DebugService` будує знімок не частіше ніж раз на `CONFIG.debug.overlayUpdateMs`
  (годинник `now` з композиції — `performance.now`); коли знімок нікому не потрібен, наступний потрібний кадр будує його
  одразу. **Замір (Node, ПК, справжні `BiteSystem` і `FISH_DB`):** зараз у базі 2 види, один знімок ~5 мкс →
  ~0,31 мс на секунду при 60 кадрах, ~0,03 мс у ритмі 150 мс (на телефоні в кілька разів більше); ціна росте лінійно з
  кількістю видів (`getLiveChances` рахує кожен вид і ~14 рядків розбивки). Разом із знімком у ритмі 150 мс приходять
  і живі оновлення відкритого DevTools (`refreshLive`) — раніше 60 на секунду. Перевірка `platform-runtime` (60 кадрів →
  6 знімків, після паузи перший — одразу) падає на старому коді (60).
- **TK-393 (v0.52.59, D3).** Смуга кадрів «ПРОДУКТИВНІСТЬ» — три `<path>` (спокійні, ривки, фрізи), прямокутник кожного
  кадру — відрізок `M x y h0.8 V36 h-0.8 Z` у `d`; лінії 60 і 30 FPS як були. У вікні 5 елементів SVG замість до 242,
  латка пише 3 атрибути замість до 240 вузлів. Перевірка `frame-profiler` (3 елементи, відрізки за кольорами) падає на
  старому коді.
- **TK-394** — не потрібна (див. D4).
- **TK-395 (v0.52.60, D5).** `OverlayController` і `OverlayUpdateLoop` вимагають усіх колабораторів від композиції
  (`documentTarget`, `updateLoop`, `viewStateStore`, `interactionBridge`, `timer`), без `?.`-викликів і глобальних
  `document`/`window` за замовчуванням; обидві композиції передають `windowTarget`. `OverlayInteractionBridge` без
  невикористаного `rootElementProvider`, один годинник. `OverlaySettingsModule` — методи сховища без запасних гілок;
  це виявило, що фейк сховища в `config-runtime-check` не мав `subscribe` (дописано). `OverlayDomAdapter`
  (запасні гілки для DOM-дубля в `#patchNode`) лишився: їх прибирання вимагає доповнити `TestDocument`
  (`cloneNode`, `attributes`) — окрема робота. Перевірка `overlay-balance-windows` (контролер без `viewStateStore`,
  цикл без таймера — відмова) падає на старому коді.
- **TK-396 (v0.52.61, Q2).** `OverlayMetricHints` (стан відкритих підказок у `OverlayViewStateStore`, тож зміна одразу
  перемальовує вікна, а підказка — частина HTML і переживає оновлення overlay): що це, формула, кожен параметр із
  поточним значенням (`OverlayMetricResolver`, один на підказки й консоль), кнопка DevTools для параметрів, які DevTools
  показує (`CONFIG.`, `HOOKED_FISH.`, `ITEM_DB.`, `FISH_DB.`, `MAP_DB.`, без `<state>`). `metricRow` робить інтерактивною
  лише метрику з описом у каталозі (`aria-expanded`), решта — простий рядок. `OverlayMetricInfoBridge`: натиск —
  консоль і перемикання підказки; відкриття DevTools перейшло в кнопки підказки; `documentTarget`, `eventTarget`,
  `hints` — обов'язкові (фейкам каталогу дописано `dispose`). Звіт завантаження без буфера — `DevTools.showText`
  (текстовий діалог панелі) замість `prompt`. Перевірки `ui-surface` (підказка закрита → натиск відкриває під рядком,
  опис, формула, значення, кнопки лише для параметрів DevTools → другий натиск закриває; метрика без опису — простий
  рядок) падає на старому коді; `devtools-controls` (`showText` відкриває панель і діалог з текстом).
