# House interior navigation and shared header

Owner requests: 2026-10-14. The separate Fisherman's House page must allow room exploration while UI stays anchored to the screen. Latest inputs include three schematic references (closed, hover/swipe and open) and the clarified touch sequence. They supersede the fully hidden default footer; the header still follows the existing gesture contract. Visual/input acceptance remains with the owner; automated browser checks inspect console errors only.

- Each room has an independent horizontal scene viewport containing all three background light layers, aquarium artwork, fish and feed readings. They move together. Background scale follows test's cover principle: use the larger width/height scale, centre vertical overflow and fill every side of portrait, 21:9 and wider viewports without letterboxing. All five room artwork levels have the same 2752:1536 aspect ratio.
- Horizontal touch/mouse drag reveals the hidden left/right interior, clamps at room boundaries and distinguishes a click from navigation using the existing threshold. Browser image dragging cannot steal the gesture. Cancel, a second pointer, capture loss and detach must not leave a live drag or accidental click. House wheel input is reserved for vertical panel gestures; horizontal wheel input does not pan the room.
- House composes the reusable `HorizontalScrollController` in scene mode with `CONFIG.input.mapPan` injected from bootstrap. Inversion, sensitivity and gesture displacement limit match map input. Physical pointer deltas convert to logical units once below 320px. Inventory retains its native touch scrolling and existing wheel behavior.
- The header starts hidden and the footer starts as an accessible compact strip: top handle and three equal icon-only buttons. One upward gesture reveals all three labels without opening a section. A button tap opens that sheet, keeps the chosen button expanded and collapses the other two to miniatures; tapping a miniature changes the active sheet directly. A downward gesture over the backdrop or downward drag/tap on the sheet handle dismisses the sheet to the compact footer. Sheet content retains native scrolling; gestures do not steal feed-dialog input.
- On mouse desktop only, hover raises that button and reveals its label using the same geometry/appearance as the chosen button. There is no hover emulation on phones/touch/hybrid devices. The shared compact footer handle expands on an upward drag, collapses on a downward drag and toggles names on tap/keyboard activation. These three footer states are explicit UI-catalog examples backed by the production HouseView/HTML/CSS.
- Down opens the header; with the expanded footer present it first collapses names without opening the header. Up while the header is visible first closes the header without expanding the footer. Background click toggles header/expanded-menu together; closing preserves accessible miniature navigation. A wheel burst emits one command, with a new direction or an idle gap of `HOUSE_CONFIG.ui.sceneWheelGestureGapMs` (180ms) starting another gesture. Horizontal wheel input never pans House. Gestures work even when the room fits horizontally and on the miniature buttons/backdrop; renovation and feed dialogs retain their existing isolation.
- `TimeDisplay`, `FullscreenControl`, Play and DEV Tools use the shared `hud-control` appearance and 44px base height; fullscreen and DEV Tools share its square modifier. Header keeps Play in the same row. When required width exceeds available width, `HudRowSizer` computes one scale from shared CSS tokens and applies it to every header control, font, gap, border and radius. Below 320px, the existing surface conversion still applies once. The DEV toggle is mounted inside the header and remains fixed within that row; its panel stays in the portal.
- Play and the three category buttons have no decorative border. House sheets use the shared accessible `UiSheetHandleRenderer` and injected `SheetDismissController` instead of crosses. Tapping the top trigger or swiping it down shrinks the sheet's height to the existing compact footer, without translating it outside the viewport and recreating it. `SheetHeightController` owns measured heights, one pending frame, content observation and completion timers. Release chooses dismissal before reset so the height never jumps back to its full value. Upward/cancelled drags settle without replaying an entrance animation. Keyboard activation and Escape remain available, focus restores and reduced motion dismisses immediately; the sticky handle remains reachable above native scrolling content.
- Sheets always meet the bottom screen edge. The dock and sheets share one outer width (up to 1100px); the three buttons have equal flexible columns, shared gaps and side insets of 20 logical pixels on mobile or 40 above the existing 640px breakpoint. Sheet content reserves the dock height so its final rows remain reachable above the buttons; safe-area space is included.
- Footer buttons use one style in all sections: 44px logical height when compact and the existing 82/92px mobile/desktop height when expanded, with labels clipped in the compact state. The row fills the mobile width inside its required insets, and the wide layout is centred/capped. The footer has no black gradient or button glow. Header, footer and sheets share the glass-background/blur owner; the footer becomes transparent over an open sheet to avoid a second backdrop layer and the duplicate compact handle is hidden. Translucent footer and sheet surfaces have no bottom border.
- Fullscreen, clock, DEV and fishing toolbar borders use shared width/color tokens, with no fullscreen-specific green border. Index/DEV compose `GameToolbar` for the badge and visible bottom actions. The version keeps the same bottom edge and 48px logical height as those actions; when space runs out its width shrinks and excess text clips. The row uses one shared gap, while the existing 320px surface scales the whole row below that width.
- Care, save format, room upgrades, renovation, room navigation and gameplay timing remain unchanged. Open sheets keep the scene inert; disposal cancels sheet timers and gestures.
- Aquarium status retains its level segments. Current/max level readings and room duration move below the scales, with no right-hand counters. Aquarium capacity has its own label/count and a continuous shared `InventoryResourceMeterRenderer`: fill is count/current-level-capacity, grey is unused capacity and color reads remaining free capacity through the existing degradation resolver (green to red). Empty 0/0 is empty; overcapacity is clamped graphically. Reserve-feed text/count sits in the aquarium status card. The redundant next-level list is removed; the upgrade button alone names the target `Рівень 6 · Місткість 18`, using the service's next capacity.
- Aquarium and automatic-feeder installation share the primary full-width button; upgrade uses the same appearance when affordable and a muted disabled danger variant otherwise. Current configured prices are zero and there is no wallet in production. HousePresenter accepts an injected read-only available-funds port for paid affordability; without it only free costs are considered affordable. This does not create a balance, charge money or change acquisition/save semantics. Catalog demonstrates the unavailable state without storage.
- The shared control variant of the automatic switch has no surrounding border/background/padding. It is disabled and visibly inactive without usable selected feed reserve, preserving the model's enabled preference; replenishment restores the model's current mode. Disabled switches never dispatch a change. Catalog adds full-capacity, no-feed and unaffordable examples using production components/styles/labels and injected capacity configuration.
- Production, DEV House, embedded House and UI catalog compose the same components with owned listeners and cleanup. No extra continuous render loop, globals, duplicated gameplay state or per-frame DOM queries.
